AI Learning Coach IDE

TypeScript VS Code Extension API Python AST Analysis LLM (Groq) Temporal Behavior Modeling

Problem Statement

Most AI coding tools focus on correctness or auto-completion. However, competitive programming and DSA mastery depend on cognitive habits — planning, boundary reasoning, iteration strategy, and conceptual clarity. There is currently no tool that analyzes how a learner thinks while coding.

Why It Matters

In algorithmic problem solving, the process is more important than the final code. Students often pass test cases while retaining flawed reasoning patterns. This system models coding as a temporal cognitive process and provides structured pedagogical feedback without revealing solutions — reinforcing learning instead of shortcutting it.

System Architecture

Core Capabilities

Behavioral Signal Modeling

Captures micro-interactions including edit churn, undo density, idle vs active time ratios, cursor backtracking, and abandoned code paths to infer planning vs impulsive coding patterns.

AST-Level Concept Detection

Parses code into abstract syntax trees to detect off-by-one patterns, inefficient iteration structures, suspicious boundary checks, and repeated data structure rewrites.

Temporal Learning Analytics

Tracks repeated misconceptions across sessions and identifies improvement or regression trends over time. Models learning as a sequence, not a snapshot.

Structured Pedagogical Feedback

Generates reflective, evidence-based feedback including strengths, areas to investigate, reasoning impact, and metacognitive questions — without revealing hints or solutions.

Challenges & Solutions

Challenge: High Noise in Raw IDE Events

Solution: Designed a signal derivation layer that aggregates low-level events into semantically meaningful behavioral metrics before LLM processing.

Challenge: Avoiding Solution Leakage

Solution: Constrained prompt schema and structured output validation to ensure feedback remains reflective and pedagogical, not instructive.

Challenge: Interpreting Temporal Behavior

Solution: Developed planning-ratio metrics and rewrite-density heuristics to distinguish strategic iteration from conceptual confusion.

Results & Impact

Metric Outcome
Behavioral Signals Extracted 15+ engineered metrics
Feedback Latency < 5 seconds (local processing + LLM)
Solution Leakage 0% (by design constraint)

Research Angle

This project explores temporal intelligence systems — treating IDEs as event-driven cognitive observatories. It demonstrates how structured signals + constrained LLM reasoning can produce reflective educational feedback rather than direct answers.

Interactive Reinforcement Learning Pong Trainer

Python PyTorch Pygame Deep Q-Network Reinforcement Learning

Problem Statement

Reinforcement Learning algorithms are often difficult to debug, visualize, and understand in real-time. Most implementations run as silent training loops with little interpretability. This project addresses that gap by creating a fully interactive RL playground where a Deep Q-Network learns to play Pong live, with complete transparency into states, rewards, Q-values, and training dynamics.

Why It Matters

Understanding RL requires more than reading equations — it demands observing policy evolution, reward shaping effects, and stability trade-offs. This system transforms a classic control problem into a live experimental sandbox where hyperparameters, reward components, and difficulty can be modified on the fly, enabling deeper intuition about learning behavior.

System Architecture

Core Features

Live Reward Shaping Controls

Fully configurable shaping parameters including terminal rewards, action-change penalties, stabilization rewards, and distance-based shaping (α). Enables experimentation without modifying source code.

Step-by-Step Debug Mode

Manual stepping mode allows frame-by-frame execution. Displays reward and loss graphs in real time, enabling microscopic inspection of learning dynamics.

Battle (Survival) Mode

A 5-minute survival challenge where difficulty escalates every 30 seconds. Ball speed increases, paddle height decreases, and leaderboard statistics track performance.

Multiple Opponent Types

Train against a mathematically perfect intercept bot, a heuristic-based decent bot, or a human player. Enables curriculum-style training and evaluation.

Full Model Persistence

Save and load not only network weights, but optimizer state, replay statistics, reward windows, and training metrics — ensuring complete session restoration.

Technical Highlights

Component Implementation
Algorithm Double Deep Q-Network (DQN)
Network Architecture 5 → 128 → 128 → 3 (ReLU)
Replay Buffer 20,000 transitions
Batch Size 32
Target Network Updates Periodic hard update (configurable)
Visualization Matplotlib rendered into Pygame surface

Challenges & Solutions

Challenge: RL Instability & Jittery Policies

Solution: Implemented action-change penalties and stabilization rewards to encourage smoother paddle control while preserving responsiveness.

Challenge: Sparse Rewards in Pong

Solution: Designed distance-based shaping reward using predicted intercept points to provide dense learning feedback during ball travel.

Challenge: Observability of Learning Process

Solution: Built real-time reward/loss charts, Q-value display, epsilon tracking, and episode statistics directly into the game UI.

Impact & Learning Outcomes

This project bridges theory and practice by converting a textbook RL algorithm into an interactive laboratory. It provides hands-on exposure to reward shaping, exploration strategies, Double DQN stabilization, and curriculum-based difficulty progression — all within a dynamic, visual environment.

Forum for Information Retrieval Evaluation • December 2024

A Study of ML and DL approaches for Sentiment Analysis in Code-Mixed Tamil and Tulu Texts

Fifth Workshop on Speech, Vision, and Language Technologies for Dravidian Languages • May 2025

Explored sentiment classification in Tamil-English and Tulu-English code-mixed datasets using both machine learning (ML) and deep learning (DL) approaches. DL models, while theoretically capable of capturing richer contextual and semantic relationships, underperform with limited data availability. ML models are better suited for sentiment analysis of code-mixed texts, particularly in low-resource settings, as they effectively leverage n-gram-based features without requiring extensive labeled data.

My Contribution: Conducted experiments for DL, wrote manuscript.
